### 1-A. 수동 경로 순서 (2026-11-18 · 회차마다 게시 스크립트를 새로 짜던 것을 도구로 올림)

회차 폴더 = `scripts/_pdf_report/<날짜>/`(gitignore — 원본 PDF·뽑은 글자·쪽 그림·초안이 여기).

1. 원본 PDF 를 `src/` 에 두고 글자(`text.txt`)·쪽 그림을 뽑는다 → 그림은 §3-C 대로 잘라 `png/` 에.
   글자가 그림인 슬라이드 PDF(추출이 쪽당 수백 자 미만)는 쪽 렌더를 서브에이전트에 10쪽씩 받아쓰기(수치·도표 표 포함)로 맡기고
   그 합본을 `text.txt` 로 쓴다 — 그림 속 숫자는 메인이 쪽 렌더로 검산한다(Codex 는 받아쓰기와만 맞댄다 · 리포트 179).
2. `report.md` 초안(그림은 `{{PUB}}/<이름>.png`) · `batch.json` = `{"storage_folder": "<영문-폴더명>"}`.
3. 그림 업로드: `scripts/yt_report/upload.ts`(YT_RUN_DIR=회차 폴더).
4. 요약부(첫 인용·소제목·핵심 정리)를 본문과 맞대어 본다(§3-H) → Codex 사실 대조: `scripts/pdf_report/prompts/codex_check.md` 를
   회차 폴더로 복사해 `<…>` 만 채워 `codex_run.py run` · 결과는 원문으로 검산해 반영 · `check/codex_<이름>.md` 로 남긴다.
5. **회차 끝 — 작업방식 회고 «게시 전»**(사용자 지시 2026-11-18 · 2026-11-24 회고 강제): 이번 회차의 결함·Codex 지적 유형·손으로 한
   단계·회차 폴더에 새로 짠 스크립트를 하나씩 어디에 넣었는지(또는 안 고친 이유) `<회차 폴더>/retro.md` 표로 남긴다 — 「반영 자리」 칸은
   여섯 낱말만 받는다: 지시서(`prompts/codex_check.md`) · 도구 코드(`publish.py`) · 검사기 · 규칙 문서(이 문서) · 원장 · 안 고침.
   회고 «뒤»에 드러난 결함(§4 검사 — `publish.py --dry-run` 이 만든 `reports_final/` 을 읽으므로 회고 뒤에 돈다 · 게시 뒤 `verify.py`)은
   원장에만 `add` 하고 다음 회차 회고의 재료로 넘긴다. 첫 줄 `run: YYYY-MM-DD/pdf-stock_monitor:<회차 이름>` · 결함 유형은 agents 교훈 원장 갈래 `pdf-report` 로.
   🔴 **`publish.py` 가 회고 표·원장 기록이 없으면 게시하지 않고 멈춘다**(`--dry-run` 포함). 절차 정본 = agents
   `scripts/pdf_report/README.md` 「회차 끝 회고」(원장 명령은 `../agents` 에서) · 반복 교훈은 `prompts/codex_check.md` 로 옮긴다
   (agents 도구에만 맞는 교훈은 옮기지 않고 그 파일 끝 「다른 레포 교훈 — 안 옮김」 줄에 표식만).
   회차 폴더를 지우기 전에 회고 표를 §5 갱신 이력 한 행으로 옮긴다.
6. §4 검사 → 게시: `scripts/pdf_report/publish.py`(인자 = 문서 첫머리) → 무효화 → 프로덕션 `verify.py`.
   - `verify_yt_report.py` 는 영상용 `settle_report.json` 을 요구한다 — PDF 는 애니메이션이 없으니 `{}` 로 둔다(리포트 175·179 같음).
   - 무효화 = `lib.revalidate.revalidate_tags_prod(["posts", "post:<id>"])`. 회차 폴더 스크립트에서는 루트 `.env.local` 을
     `load_dotenv(<루트>/.env.local, override=True)` 로 직접 읽는다 — 안 읽으면 「PROD_URL 미설정」 경고만 내고 조용히 건너뛴다.

## 2. 원문 보존이 제1 원칙

- **원본의 표·이미지를 그대로 보존**한다. 다시 그리거나 mermaid 로 재구성하지 않는다
  (`report.md` §3-6). 비교를 위해 **새 표를 더하는 것**은 된다.
- 본문에 넣을 페이지 이미지는 **Storage 에 올린 공개 URL** 로만 참조한다. 로컬 경로(`*_files/...`)는 깨진다.
- 🔴 **원본 PDF 는 기본이 「올리지 않는다」이다 — 발행처의 인터넷 링크로 대체한다**(사용자 지시
  2026-09-15). 아래 §2-A 가 절차다. `posts.file_path` 첨부는 **링크를 못 찾았을 때만** 쓴다.
- 사외비 문서면 `is_confidential = true` + **원문 파일을 public 버킷에 올리지 않는다**(`report.md` §2-C).

### 2-A. 🔴 PDF 를 받으면 먼저 원문 URL 을 찾는다 (사용자 지시 2026-09-15)

> _"db 용량 줄이기 위함인데 한국자동차연구원이나 한국자동차모빌리티산업협회 등 인터넷 링크를 찾을 수
> 있는 소스는 pdf 업로드 하지말고 링크로 대체해. 내가 pdf를 주고 보고서를 만들라 해도 출처 보고
> 인터넷 url 검색해서 첨부해."_

사용자가 PDF 파일을 건네줘도 **그 파일을 Storage 에 올리는 것이 기본값이 아니다.** 순서는 이렇다.

1. **출처를 읽는다** — 표지·머리말·파일명에서 발행기관과 발행일, 호수를 잡는다.
   파일명이 `250707 (산업분석 특별호) …` 처럼 날짜를 앞에 달고 오는 경우가 많다.
2. **그 기관 사이트에서 원문을 찾는다** — WebSearch 로 찾고, **반드시 WebFetch 로 열어 확인**한다.
   🔴 **못 찾으면 「미확인」으로 그대로 둔다. 그럴듯한 URL 을 지어내지 않는다.**
3. **찾았으면** `posts.source_url` 에 넣고 `file_path`·`file_name` 은 **비운다**(PDF 업로드 없음).
4. **못 찾았으면** 종전처럼 PDF 를 올리고, 왜 못 찾았는지 한 줄 남긴다(비공개 자료·회원 전용 등).

본문(`posts.content`)은 어느 쪽이든 그대로 쓴다 — 링크로 바꿔도 **화면에 보이는 보고서는 안 변한다.**
바뀌는 것은 원문 첨부가 우리 Storage 냐 발행처 사이트냐 뿐이다.

#### 기관별로 확인된 링크 형식

| 기관                              | 형식                                                                 | 잡는 법                                                                              |
| --------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 한국자동차연구원(KATECH) 산업분석 | `…/page/07090450-…-ee74cbb3e738?ac=view&post=<post_key>`             | 목록 HTML `<tr data-post_key>` 에서 키를 캔다. 목록은 `?page=N`(10건씩)              |
| KATECH 모빌리티 인사이트          | `…/page/aeacfe71-…-64a0c6d3f007?ac=view&post=<post_key>`             | 산업분석과 같은 방식(게시판 페이지 id 만 다르다)                                     |
| 한국자동차연구원 PDF 직링크       | `https://www.katech.re.kr/download/<file_uuid>`                      | 상세페이지 HTML 의 `/download/…`. `Content-Disposition` 에 원본 파일명이 그대로 온다 |
| 산업연구원(KIET) 월간 산업경제    | `https://www.kiet.re.kr/research/economyDetailView?detail_no=<번호>` | 글 하나마다 상세페이지가 있다. 첨부 파일명에 호수가 든다(리포트 175 = 제337호)       |
| 그 밖                             | 기관 게시판 상세페이지 우선, 없으면 PDF 직링크                       | 직링크는 재업로드로 바뀔 수 있어 상세페이지를 먼저 쓴다                              |

🔴 **KATECH 목록에서 제목 링크를 그대로 긁으면 `href=""` 라 빈 값이다.** 실제 주소는 `data-post_key`
속성에 있고 클릭 시 JS 가 `?ac=view&post=<key>` 로 조립한다. 2026-09-15 에 이걸 모르고
`#vol166` 같은 **가짜 앵커**를 넣은 글이 7편 있었다(열어도 목록 첫 화면으로만 간다).

⚠️ **목록 맨 위 `data-post_key` 는 최신호가 아니라 `[안내]` 공지일 수 있다**(2026-10-30 실측 — 첫 키를 Vol.173 으로 잘못 짚었다).
키는 `<tr>` 줄 순서대로 제목과 짝지어 고르고, 상세페이지를 열어 제목·첨부 파일명을 확인한다.

## 3. 실제로 터진 결함과 처방

### 3-A. 🔴 표 셀의 `<br>` 가 글자 그대로 보였다 (수리 완료)

**리포트 115**(중국산 자동차 수출 확대에 따른 관세·보조금 대응)의 표에서 `EU<br>(통상규제+현지생산)` 가
화면에 **`<br>` 라는 글자 그대로** 찍혔다. 원본 HTML/PDF 표를 옮길 때 셀 안 줄바꿈으로 `<br>` 를 쓰는데,
렌더러(`components/reports/markdown-view.tsx`)에 `rehype-raw` 가 없어 **인라인 HTML 을 전부 평문으로**
내보내고 있었다. `report.md` §4 의 _"표 셀 안 `<br>` 는 보존되므로 사용 가능"_ 이라는 서술이 틀렸던 것이다.

**수리(2026-09-11)**: `rehypePlugins = [rehypeRaw, rehypeSanitize]`.
🔴 **순서를 바꾸거나 sanitize 를 빼면 XSS 가 열린다** — 본문에는 외부 웹·PDF 를 LLM 이 요약한 결과가
들어오므로 적대적 원문의 `<img onerror=…>` 가 섞일 수 있다.

**작성 규칙**: GFM 표 셀 안에서 줄을 바꾸는 문법은 `<br>` 뿐이다. 계속 써도 된다.
단 **단독 줄 `<br>`** 는 여전히 쓰지 않는다(다음 문단을 HTML 블록으로 삼킨다 — 전처리가 지운다).

### 3-B. 스캔 PDF 는 텍스트 추출이 0자다

글자가 이미지로만 들어 있는 스캔본은 `pdfjs`/`pypdf` 로 뽑으면 **빈 문자열**이 나오는데 오류는 안 난다.
→ `pymupdf` 로 렌더한 뒤 vision 으로 읽는다. 상세 = [`gotchas-data-collection.md`](./gotchas-data-collection.md).

### 3-C. 본문 이미지 판정은 쪽당 밀도로

`scripts/lib/pdf_figures.py` 는 **쪽당 이미지 밀도**로 본문 도판을 가른다. 총 길이로 재면 오판하고,
재무제표 부록은 건너뛴다. 이 판정을 바꾸지 말 것.

### 3-D. 캡션이 그림에 없는 것을 약속하지 않게

유튜브 경로와 **같은 규칙**이다([`report-from-youtube.md`](./report-from-youtube.md) §2-B).
PDF 는 애니메이션이 없어 §2-A(차오르는 중 캡처)는 해당 없지만, **캡션에 적은 수치가 그 페이지 이미지에
실제로 있는지**는 똑같이 확인한다. 원문 다른 쪽의 수치를 캡션에 옮겨 적는 실수가 흔하다.

### 3-E. 디자인된 백서는 «펼침면»이라 쪽 렌더가 두 쪽짜리로 나온다

ABB 백서(2026-09-11 실측)는 PDF 20쪽인데 **본문은 37쪽**이었다. 표지만 A4 한 쪽이고
나머지는 **왼쪽 쪽 + 오른쪽 쪽을 붙인 펼침면**이라, 쪽을 통째로 렌더하면 «두 쪽»이
한 장에 담긴다. 그대로 본문에 넣으면 도해 하나를 보려고 관계없는 본문 단을 같이 봐야 한다.

**처방**: 쪽을 먼저 렌더해 눈으로 배치를 확인하고, `fitz` 의 `clip` 으로 **비율 좌표**를 줘
도해가 있는 반쪽만 잘라낸다(이 백서는 도해가 전부 오른쪽 반이었다).

```python
clip = fitz.Rect(r.x0 + r.width*0.51, r.y0 + r.height*0.06, r.x1, r.y0 + r.height*0.74)
pix = pg.get_pixmap(dpi=200, clip=clip)
```

- 도해·표는 **200dpi 면 화면에서 충분**하다(파일 100~500KB). 사진은 더 커진다.
- 🔴 **자른 뒤 반드시 `Read` 로 열어 볼 것.** 머리글·쪽번호가 걸려 들어오는 일이 흔하고
  (실측 1건), 캡션에 「무엇이 보인다」고 쓰려면 어차피 봐야 한다(§3-D).
- 쪽 번호는 **PDF 쪽**과 **문서 쪽**이 다르다. 부록의 그림 목록은 «문서 쪽» 기준이므로
  그대로 믿고 찾으면 엉뚱한 쪽이 나온다.

### 3-F. 🔴 작성일을 한국 시각 자정으로 넣으면 화면에 하루 앞당겨 보인다

`source_published_at` 에 `2026-10-21T00:00:00+09:00` 을 넣었더니 상세 화면 작성일이 **2026.10.20** 으로 찍혔다
(리포트 147, 2026-10-30 · 같은 날 고침). 한국 자정은 UTC 로 전날 15시이고 화면은 그 날짜를 보여 준다.
**처방**: 원문 날짜는 **UTC 자정 `YYYY-MM-DDT00:00:00Z`** 로 넣는다 — 기존 글 대부분이 이 형식이다.

### 3-G. 🔴 강조 깨짐을 정규식으로 «일괄» 고치면 짝을 잘못 잡아 멀쩡한 문장을 깬다

리포트 175(2026-11-17): 닫는 `**` 앞의 부호 문제를 정규식 한 번으로 고쳤더니, 한 줄에 강조가 둘 있는 문장에서
앞 강조의 «닫는» `**` 를 «여는» 것으로 잡아 `…거점)와** 부품 클러스터**를` 처럼 새로 깨뜨렸다. 검사기도
「여는 `**` 바로 뒤가 공백」 형태와 `»` 부호를 못 봐 게시 뒤 `verify.py` 에서야 별표 2곳이 드러났다.
**처방**: 깨짐은 검사기가 찍는 자리를 하나씩 손으로 고친다 · 검사기는 유니코드 부호 전체와 공백 형태를 보게 고쳤다
(`verify_yt_report.py` 표본 추가) · `verify.py` 는 별표가 보이면 앞뒤 글자를 찍는다.

「바뀌었다」 · 원문의 「등」 예시를 「다섯 가지다」로 한정 · 「~에 그치지 않고 함께」를 「~이 아니라」로 양자택일화.
유튜브 작성 지시서(`scripts/yt_report/prompts/write.md` 2번 규칙)와 같은 경향이다. **Codex 대조 «전»에** 그 규칙대로 맞대어 본다.

## 4. 게시 전 필수 검사

```bash
python scripts/verify_yt_report.py --run <산출물 폴더>   # 본문 기계 검사(유튜브·PDF 공용)
```

- `report.md` §8 체크리스트를 그대로 따른다.
- 렌더 확인은 **게시 뒤 프로덕션에서** `YT_RUN_DIR=<폴더> python scripts/yt_report/verify.py --ids <id>`
  (로봇 글은 `--route humanoid/reports` 로 한 번 더) — dev 서버는 디스크를 채워 쓰지 않는다(사용자 지시 2026-11-17).
  🔴 3-A·3-G 가 정확히 「기계 검사는 통과하는데 화면에서만 깨지는」 종류였다. 그 폴더에 `batch.json`
  (`{"storage_folder": …}`)이 있으면 `upload.ts`·`verify.py` 를 그대로 쓸 수 있다.
- **두꺼운 잡지(수십 쪽)의 Codex 사실 대조는 범위를 둘로 나눠 병렬**로 맡긴다(꼭지 경계로 자르고 「들어가며」·「핵심 정리」의
  앞뒤 요약 문장은 양쪽 모두 원문으로 확인하게 한다). 모빌리티 인사이트 Vol.45(88쪽)에서 지적 12건이 모두 맞았고,
  대부분 「~할 수 있다」 「가능성이 크다」 같은 단서가 요약에서 단정으로 바뀐 것이었다.
- 운영 화면을 헤드리스로 잴 때 — 본문은 **안쪽 영역에서 스크롤**돼 `full_page` 캡처가 첫 화면만 찍고, 그림은
  **지연 로딩**이라 「로드 0장」으로 나온다. 결함이 아니다 — 요소로 스크롤해 찍는다. 게시 직후 첫 요청은 옛 캐시라 두 번 연다.
