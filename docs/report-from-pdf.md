## 2. 원문 보존이 제1 원칙

- **원본의 표·이미지를 그대로 보존**한다. 다시 그리거나 mermaid 로 재구성하지 않는다
  (`report.md` §3-6). 비교를 위해 **새 표를 더하는 것**은 된다.
- 본문에 넣을 페이지 이미지는 **Storage 에 올린 공개 URL** 로만 참조한다. 로컬 경로(`*_files/...`)는 깨진다.
- 원본 PDF 자체는 `posts.file_path`/`file_name` 으로 첨부한다(본문 이미지가 아니다).
  상세 페이지가 다운로드 링크를 만든다.
- 사외비 문서면 `is_confidential = true` + **원문 파일을 public 버킷에 올리지 않는다**(`report.md` §2-C).

## 3. 실제로 터진 결함과 처방

### 3-A. 🔴 표 셀의 `<br>` 가 글자 그대로 보였다 (수리 완료)

**리포트 115**(중국산 자동차 수출 확대에 따른 관세·보조금 대응)의 표에서 `EU<br>(통상규제+현지생산)` 가
화면에 **`<br>` 라는 글자 그대로** 찍혔다. 원본 HTML/PDF 표를 옮길 때 셀 안 줄바꿈으로 `<br>` 를 쓰는데,
렌더러(`components/reports/markdown-view.tsx`)에 `rehype-raw` 가 없어 **인라인 HTML 을 전부 평문으로**
내보내고 있었다. `report.md` §4 의 _"표 셀 안 `<br>` 는 보존되므로 사용 가능"_ 이라는 서술이 틀렸던 것이다.

**수리(2026-09-11)**: `rehypePlugins = [rehypeRaw, rehypeSanitize]`.
🔴 **순서를 바꾸거나 sanitize 를 빼면 XSS 가 열린다** — 본문에는 외부 웹·PDF 를 LLM 이 요약한 결과가
들어오므로 적대적 원문의 `<img onerror=…>` 가 섞일 수 있다.

**작성 규칙**: GFM 표 셀 안에서 줄을 바꾸는 문법은 `<br>` 뿐이다. 계속 써도 된다.
단 **단독 줄 `<br>`** 는 여전히 쓰지 않는다(다음 문단을 HTML 블록으로 삼킨다 — 전처리가 지운다).

### 3-B. 스캔 PDF 는 텍스트 추출이 0자다

글자가 이미지로만 들어 있는 스캔본은 `pdfjs`/`pypdf` 로 뽑으면 **빈 문자열**이 나오는데 오류는 안 난다.
→ `pymupdf` 로 렌더한 뒤 vision 으로 읽는다. 상세 = [`gotchas-data-collection.md`](./gotchas-data-collection.md).

### 3-C. 본문 이미지 판정은 쪽당 밀도로

`scripts/lib/pdf_figures.py` 는 **쪽당 이미지 밀도**로 본문 도판을 가른다. 총 길이로 재면 오판하고,
재무제표 부록은 건너뛴다. 이 판정을 바꾸지 말 것.

### 3-D. 캡션이 그림에 없는 것을 약속하지 않게

유튜브 경로와 **같은 규칙**이다([`report-from-youtube.md`](./report-from-youtube.md) §2-B).
PDF 는 애니메이션이 없어 §2-A(차오르는 중 캡처)는 해당 없지만, **캡션에 적은 수치가 그 페이지 이미지에
실제로 있는지**는 똑같이 확인한다. 원문 다른 쪽의 수치를 캡션에 옮겨 적는 실수가 흔하다.
