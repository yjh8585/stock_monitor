## P1. 수집기 계통 코드 버그 (최우선 — 한 번 고치면 대량 자동 정정)

### ☐ P1-1. fnguide 분기 Q4 = 연간 누적값 (153개사) — `q4_annual_bug`
- **증상**: `financials`의 `period_type='quarterly' AND fiscal_quarter=4` 행에 **연간 누적값**이 들어감(Q1~Q3는 정상 discrete). 소스: fnguide 149 + pykrx+dart 4(현대모비스·현대위아·에이치엘만도·한국무브넥스) + 부품사 LG전자(066570).
- **예**: 넥센타이어 FY2025 Q4=3,189,600(=연간, 실제 Q4≈833,000). 현대모비스 Q4=61,118,100(=연간, 실제≈15.4조).
- **영향**: **연간(annual) 행은 정상.** 분기 절대값·분기합/TTM·Q4 차트만 오염. 라이브 카드(latest_quarter YoY)는 Q4끼리 annual-vs-annual이라 성장률 %는 우연히 자기정합 → 실害는 (a)4Q 절대매출 오표시 (b)분기합·TTM (c)역사 Q4 차트.
- **재현 쿼리**:
  ```sql
  select q.company_id, q.fiscal_year
  from financials q
  join financials a on a.company_id=q.company_id and a.fiscal_year=q.fiscal_year and a.period_type='annual'
  where q.period_type='quarterly' and q.fiscal_quarter=4 and q.revenue = a.revenue;
  ```
- **수정 대상**: `scripts/collect_financials.py`(fnguide/yfinance 재무 파서 — 표 인식 L385~510, `_find_quarterly_table` L410, 분기 적재 L510). fnguide 분기표는 헤더가 `03/06/09`만이라(L419) Q4=12 열이 어디서 유입되는지 추적 필요. 후보: 연말(12월) 열이 quarterly Q4로 잘못 적재되거나 yfinance `quarterly_income_stmt`의 누적/12월 컬럼.
- **정정 방법**: 수집기에서 **discrete Q4 = 연간 − (Q1+Q2+Q3)** 로 도출해 저장하거나, 12월 누적 열을 quarterly로 저장하지 않는다. 코드 수정 후 재현 쿼리로 나온 153건 재수집.

### ☐ P1-2. fnguide 대차대조표 부채총계 오파싱 — TL==TA (79개사·217행)
- **증상**: `total_liabilities` 컬럼에 **`부채및자본총계(=자산총계)`** 값이 들어가 `부채=자산`. 회계항등식 `자산=부채+자본` 위반(초과분=자본총계). 소스: fnguide 76 + dart 2(에스케이온·현대트랜시스) + pykrx+dart 1(현대위아).
- **예**: 넥센타이어 FY2022 부채=자산=3,944,336(실제 부채 2,348,105). 한국앤컴퍼니 FY2022~25.
- **영향**: **부채비율·자기자본비율·레버리지 지표 전부 오염**(자산·자본·매출은 정상).
- **재현 쿼리**:
  ```sql
  select company_id, fiscal_year, period_type, data_source
  from financials
  where total_liabilities is not null and total_assets is not null
    and total_liabilities = total_assets and total_liabilities <> 0
    and coalesce(total_equity,0) <> 0;
  ```
- **수정 대상**: `scripts/collect_financials.py` 계정맵(L75 `'부채총계':'total_liabilities'`) + 대차대조표 파싱. **`_match_acct` 방식의 정확일치**로 `'부채총계'`가 `'부채및자본총계'/'부채와자본총계'`를 잡지 않게(현행 부분매칭 추정). DART audit 경로는 이미 `_match_acct` 존재 — fnguide 파서에 동일 가드 이식.
- **정정 방법**: 코드 수정 후 재수집. 즉시 정정도 가능(`부채총계 = 자산총계 − 자본총계`, 자본총계는 정상). 217행은 재현 쿼리로 산출.
