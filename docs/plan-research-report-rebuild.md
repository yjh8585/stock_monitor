# 증권사 리포트 페이지 재작성 계획 (2026-08-25)

대상: `/humanoid/research` · `/humanoid/research/[id]` 와 그 뒤의 요약 파이프라인.

## 사용자 지시 원문

> 휴머노이드 증권사 리포트 페이지 수정사항.
>
> - 지금 장난하냐? 증권사 레포트를 잘 정리해서 내용을 충실하게 집어넣야지. 대충 정리하면 어떻게 해? 이미지 중 필요한 것은 수록하고. 다른 보고서 페이지에서 만들 듯 제대로 만들어야지.

> 이렇게 만든 이유가 뭐야? 그리고 어떻게 다시 만들면 좋을지 나한테 보고하고 작업해

> 아 그리고 증권사 레포트 특성상 레포트 뒷편에 재무실적들 표로 정리해 놓는데 그건 정리할 필요없어. 어차피 재무실적 중 중요한 것은 기업 페이지에 나오니까.

## 진단 (실측 2026-08-25)

`research_reports` 144건 전량 요약 완료 상태에서 잰 값.

| 항목           | 실측값                 |
| -------------- | ---------------------- |
| 요약 평균 길이 | 1,223자                |
| 최장 / 최단    | 2,101자 / 248자        |
| 델타 모드      | 37건 (26%)             |
| 본문 이미지    | 0건 (컬럼 자체가 없음) |

원인 네 가지.

1. **요약 지시문이 `/reports` 와 다른 규칙으로 쓰였다.** 정본은 agents 레포
   `apps/orchestrator/src/summarizeReportCmd.ts` 이고 거기 「세 꼭지·900~1,500자」로
   못 박혀 있다. 반면 `report.md` §3-A 는 원문 분량에 비례해 3,000~8,000자·8~15섹션을
   요구한다. 본문을 40,000자까지 읽어들이면서 1,200자로 줄이라고 지시한 셈이다.
2. **델타 모드가 상세 페이지에서 무너진다.** 「직전 대비 변화만 400~900자」는 목록을
   훑을 때만 성립한다. 상세를 열면 그 리포트 자체 내용이 없는 쪽지 한 장이 남는다.
3. **이미지가 애초에 범위 밖이었다.** 파이프라인이 `page.get_text()` 로 글자만 뽑아
   차트·표를 통째로 버린다.
4. **상세 페이지 UI 가 `/reports/[id]` 보다 얇다.** 원본 자료 카드·원문 임베드·목차가 없다.

## 단계

1. **요약 지시문 재작성** (agents `summarizeReportCmd.ts`) — 6~10섹션·3,000~6,000자·
   GFM 표 재현·`report.md` §4 렌더 규칙·재무제표 부록 제외·이미지 삽입 규칙.
2. **델타 폐기** — `summarize_naver_research.py` 가 항상 full 로 부르되 직전 요약이 있으면
   변화 섹션을 요구한다. `is_delta` 컬럼은 「변화 섹션이 있다」는 뜻으로 의미만 바꾼다.
3. **이미지** — `scripts/lib/pdf_figures.py` 신설(영역 검출·순수 함수+테스트) →
   Storage `reports` 버킷 `research/<kind>_<nid>/…png` 업로드 →
   `research_reports.images jsonb` 에 기록 → 재료 파일에 목록을 실어 헤드리스가 고른다.
4. **UI** — `/humanoid/research/[id]` 에 원본 자료 카드·목차·PDF 링크 보강.
5. **선별 재요약** — `--force --priority`(결정 7·8). 무엇이 뽑혔는지는 `--list-only`.
6. **목록 숨김** — `getResearchData` 가 새 규격(`>` 로 시작)만 select 한다(결정 9).
