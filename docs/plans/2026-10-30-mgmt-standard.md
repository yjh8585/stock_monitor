## 원문 실측 (2026-10-30, 전수)

- 문서 1,049건 본문을 Domino Data API 로 받음 → `참고/경영표준/원본/`(git 제외) · `census.json` 이 문서별 행
- 본문 ≈ 270만 자. 첨부 ≈ 2,200개·930MB 이나 대부분 개정이력·빈 양식 · 업무체계도 198개
- 부서기준서 613건 중 501건은 제목만 있는 빈 문서 · 협력사 지침 40건 = 20종 × 한/영
- 본문 속 `<img>` 는 대부분 첨부 아이콘(`/icons/medoc.gif`) — 실제 그림은 소수

## 전제 정정 (심문 중 실측)

- 보고서 목록 정렬은 게시일·원문 발행일 두 가지뿐(`lib/reports/sort.ts`) → 결정 7
- `PostRepository.list` 의 `excludeCategory` 는 **문자열 하나**(현재 로봇) → 여러 개를 받도록 고친다(`getDistinctCategories` 도)
- 게시는 `scripts/_iatf_vda_publish.ts` 처럼 `posts` 에 직접 insert · 카테고리를 지정(자동 분류기 미경유) · `is_confidential: true`

## 단계

1. **묶음 만들기** — 문서를 19개 분야에 배정하고 분야별 텍스트 묶음(`참고/경영표준/묶음/NN_분야.md`)을 만든다.
   검증: 대상 문서 전부가 정확히 한 분야에 들어갔는지 스크립트로 센다(누락 0 · 중복 0).
2. **그림·첨부 선별 수집** — 본문 속 실제 그림, 매뉴얼 방침·MAP, 업무체계도, 위임전결·표준체계도 부표,
   협력사 지침 PDF(한글판). 엑셀은 Excel COM 워크시트 단위로 렌더(`gotchas-data-collection.md`).
3. **지식노트 19편** — 서브에이전트 5개씩 4웨이브. 노트마다: 하는 일 · 문서 목록 표 · 업무 흐름 · 숫자 기준 ·
   책임과 권한 · 양식 이름 · 다른 분야 연결 · 근거 문서번호 · 「원문에 없음」.
4. **원문 대조** — 웨이브마다 Codex 가 노트↔묶음 대조 → 지적을 Claude 가 원문으로 확인해 반영.
5. **종합 보고서 13편** (00~11 + 부록 2) — 회사가 일하는 순서로. 업무체계도는 Mermaid 로 다시 그린다.
6. **화면** — 아래 짝짓기 표대로.
7. **검증·게시** — `npm run check-all` · 게시 전 검사(`verify_translationese.py`) · 헤드리스 화면 확인 · `report-review-panel`.
