#### 상세

- 앞 결정과의 관계: 2026-11-09 사용자 결정 「흑자 회사 실적 차트는 0 기준 축(음수 갈래는 적자가 있을 때만)」은 A7(이익률 숫자 표시)에서도 그대로 둔다. 숫자가 겹치면 사용자에게 묻는다(chart-guide §4-F 와 충돌 가능).
- Codex 계획서 대조(2026-11-11 15:23)는 Codex 사용 한도로 실행되지 않았다 — 메모리 지시대로 서브에이전트로 갈음하지 않고, 전제는 구현 중 메인이 코드로 확인한다.

**A 이행 상세(2026-11-11)**

- R5 원화 환산: VND 는 yfinance 에 KRW 직통이 없어 USD 교차(USDKRW ÷ USDVND)로 수집 — 2024-01~ 백필. 1조 이상 「조원」· 미만 「억원」. 환율이 없으면 「—」. 12월 결산만 전제(`krw.ts` SHORTCUT — 지금 고객사 11곳 전부 12월 결산, DB 확인).
- R6 요약 실적: 국내(`dart_corp_code` 있음) = financials 그대로 · 해외 = `pickCustomerEarnings`. 스텔란티스 요약 0.7% + 「조정」 = 상세 0.68% 와 일치(촬영 확인).
- R3 신호등: 「한 자릿수」 문구는 낮은 1~3% · 중간 4~6% · 높은 7~9% 로 읽고 이유에 「…로 해석」을 밝힌다(지어낸 숫자로 보이지 않게). 「lower end of」·「down to」는 감소로 읽지 않는다.
- A9 물량 차트: 분기 보기를 새로 두고 **MarkLines 분기가 있으면 늘 분기가 기본**(계획서의 「회사 발표가 분기만 있으면」 조건보다 넓다 — 국내 3사도 분기 기본). 분기·연간은 막대 비교, 월간은 기존 영역 + 선 그대로. 분기 창 8(12분기는 숫자가 붙었다).
- A3 속도: `loading.tsx` 를 상세뿐 아니라 요약(`/customers`)에도 둠. 실측(로컬 운영 빌드) 상세 첫 이동 1.95~2.75초 → 0.95~1.29초 · 요약 첫 진입 6.04초 → 3.94초.

**A diff 검토 반영(2026-11-11)** — Codex 는 사용 한도로 못 돌았다(exit 3). 사용자가 「클로드로 작업하던가」라 해 오퍼스 검토자 2명(독립)으로 진행.

- 반영 — 중요: 요약 캐시의 `exchange_rates` 태그를 뺐다. 환율 수집이 매시간이라 무거운 요약 캐시가 매시간 버려진다(`isr-write-optimization.md` ⑤ 와 같은 꼴). 원화 칸은 끝난 분기 평균이라 하루 캐시로 충분.

- 반영 — 사소: 장부상 이익률 전망은 전년 점의 영업이익이 조정 값이면 견주지 않음 · 영업이익률 용어 설명에서 회사 이름 뺌 · 소수 오차 시험을 실제로 오차가 나는 값(4.1·16.1 백만)으로 · 1분기만 있는 해 라벨 「YTD(1분기)」 · 조정 지표 코드를 `ir.ts` 상수 타입으로 묶음 · 현대 차트 두 파일의 이익률 레이블 상수를 `chartStyle.ts` 로.
