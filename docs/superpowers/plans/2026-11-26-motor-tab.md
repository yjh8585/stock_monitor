# 「모터」 탭 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/humanoid/motor` 탭을 만든다. 국내 모터·액추에이터·모터 제어 회사를 4개 유형 버튼과 「공급 이력」(확인 등급만) 칸으로 보여 준다.

**Architecture:**
- 명단 정본 JSON(`참고/모터회사/motor_companies.json`, git 제외)에서 검사기 겸 시드 생성기가 SQL 시드 마이그레이션을 만든다.
- DB 는 `companies` 에 `motor_types`·`supply_history` 를 더하고, 새 뷰 `motor_stocks_view` 를 둔다.
- 화면은 `DomesticTable` 에 `variant='motor'` 를 더해 휴머노이드 「기업」 탭 골격을 그대로 쓴다.

**Tech Stack:** Next.js 16(`'use cache'`·`cacheTag`) · Supabase Postgres(마이그레이션·트리거·뷰) · Python 3(`scripts/venv`, pytest) · vitest

**Spec:** [`docs/superpowers/specs/2026-11-26-motor-tab-design.md`](../specs/2026-11-26-motor-tab-design.md)
- 확정 결정 7개는 spec 3절에 있다.
- 지시 원문은 [`docs/plans/2026-11-26-motor-companies_최초지시.md`](../../plans/2026-11-26-motor-companies_최초지시.md) 에 있다(밤사이 운영 지시 포함).
- 이행 기록은 실행 시작 때 `docs/superpowers/plans/2026-11-26-motor-tab_결정이행.md` 로 만든다.

## Global Constraints

- **LLM API 호출 금지.** `enrich_company.py` 의 메타 단계와 web_search 재무 폴백은 API 키 과금이다(API 위임은 2026-11-12 에 꺼졌다).
  - 재무 수집은 `--skip-meta` 로 돌린다.
  - 대상은 `data_source ∈ {'fnguide','dart'}` 인 회사만이다.
- 유형 값은 정확히 `'auto_motor' | 'robot_motor' | 'actuator' | 'control'` 이다. 라벨은 `자동차 모터` · `로봇·산업 모터` · `액추에이터` · `인버터·제어` 이고, 이 순서로 고정한다.
- 공급 이력 값은 DB·JSON·TS 가 같은 문자열을 쓴다.
  - 등급: 한글 그대로 `'확인' | '추정'`
  - 분야: `'auto' | 'robot' | 'industrial'`
- **화면에는 「확인」만 보인다.** 뷰가 한 번 거르고 매퍼가 한 번 더 거른다.
- 공급 이력에는 실제 납품·양산 수주·공급 계약만 싣는다. 개발 협약·승인도 제출·국책과제는 싣지 않는다.
- 기존 `customers` 정규화 트리거(`expand_customer_name`)는 건드리지 않는다.
- `cacheTag('exchange_rates_live')` 를 붙이지 않는다(ISR Write). 캐시 수명은 `cacheLife('hours')` 다.
- 마이그레이션 이름은 `supabase/migrations/20261126000001_*.sql` 부터 시작한다. 기존 파일은 수정하지 않는다.
- `trg_auto_page_mapping` 은 **운영 DB 의 현재 정의**를 기준으로 고친다. 현재 정의는 robot_roles 를 먼저 보고 그다음 data_source 로 가른다. uzauto-pdf 갈래는 되살리지 않는다.
- 새 회사에는 `robot_roles` 를 주지 않는다.
- 코드 주석·커밋 메시지는 한국어로 쓴다. 파일은 UTF-8(BOM 없음)·LF 로 저장한다.
- `lib/database.types.ts` 는 통째로 덮지 않는다. 끝의 `TableRow`·`ViewRow` 는 손으로 붙인 코드다(`docs/gotchas-ci-deploy.md` §7).
- 커밋은 경로를 하나씩 지정해 스테이징한다(`git add -A` 금지). 워킹트리에 다른 세션의 미커밋 변경이 있다.

## Review Focus

1. **「추정」 공급 이력이 화면으로 샌다.** 원인은 뷰 필터 누락이나 매퍼의 등급 미확인이다. 기대: 화면에 0건. → Task 3 SQL 단언 + Task 6 매퍼 시험
2. **`supply_history` 가 null·객체·깨진 항목인 행.** 기존 회사 수백 곳이 null 이다. 기대: 빈 배열로 렌더하고 예외가 나지 않는다. → Task 6 매퍼 시험
3. **로봇 전용 회사가 `/domestic` 에 들어간다.** 원인은 트리거 판정이나 시드의 명시 `company_pages` 오류다. 기대: `include_domestic=false` 인 회사의 domestic 연결 0건. → Task 3 트리거 단언 + Task 5 사후 SQL
4. **모터와 무관한 새 회사의 페이지 매핑이 바뀐다(트리거 회귀).** 기대: `motor_types` 가 없고 `data_source='dart'` 인 회사는 지금처럼 domestic 만 받는다. → Task 3 트리거 단언
5. **재무 수집이 web_search 폴백으로 새서 API 과금이 생긴다.** 원인은 `data_source` 가 비거나 `'other'` 인 회사가 대상에 섞이는 것이다. 기대: 대상 목록에 fnguide·dart 만 있다. → Task 5 대상 함수 시험
