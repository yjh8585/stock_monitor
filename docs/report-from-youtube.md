## 1. 한 줄 원칙

**그림이 캡션을 배신하는 것**이 사용자가 반복해서 지적한 결함이다.

## 2. 실제로 터진 결함과 처방

### 2-A. 🔴 애니메이션이 차오르는 중간을 캡처한다 (가장 빈번)

해설 영상의 도해는 **한 번에 그려지지 않는다.** 막대가 하나씩 자라고 표의 칸이 차례로 채워진다.
그 도중을 캡처하면 **표는 분명히 보이는데 비교 대상이 비어 있는** 그림이 실린다.
사람 눈으로 「표가 있다」를 확인하고 통과시키기 때문에 가장 잡기 어렵다.

| 사고                  | 캡션이 약속한 것                        | 실제 그림                                         |
| --------------------- | --------------------------------------- | ------------------------------------------------- |
| 리포트 117 (딥다이브) | 체리·BYD·지리 수출량 **비교**           | 체리 막대만 참, BYD·지리는 축 라벨만              |
| 리포트 122 (대신TV)   | 폭스바겐·도요타 **직원 수 대비 판매량** | 직원 수 행만 참, 판매량 행이 빈칸                 |
| 2026-09-11 v1         | 1분기 실적표                            | 영업이익 행이 빈칸, 영업이익률이 `6.0o` 타이핑 중 |
| 2026-09-11 v1         | 부문별 총이익률 **3개 비교**            | 차량SW 한 칸만 참                                 |
| 2026-09-11 v2         | 체리 러시아 2022·2023·2024              | 2024년 값 라벨만 아직 안 뜸                       |
| 2026-09-11 v2         | 베트남 베스트셀링 1~5위                 | 막대가 다 안 자라 **1위가 제일 짧게** 보임        |
| 2026-09-11 v5         | 합성데이터 라벨 타일                    | 10칸 중 7칸만 참                                  |

**처방 — 세 겹으로 막는다.**

1. **기계**: `python scripts/yt_report/settle.py --check` 를 **게시 전에 반드시** 돌린다.
   선택한 시각 이후 8초를 훑어 **같은 장면인데 잉크(배경 아닌 픽셀)가 더 많은 프레임**이 있으면
   「차오르는 중」으로 잡고 더 늦은 시각을 권한다. 토큰 0.
2. **사람**: 검사기가 잡은 것은 **현재 프레임과 권장 프레임을 나란히 놓고** 눈으로 확정한다.
   🔴 **검사기는 후보를 좁히는 도구이지 최종 판정자가 아니다** — 자막이 길어지거나 하단 고지 띠가
   흐르기만 해도 잉크가 늘어 오탐이 난다(51장 중 1건).
3. **캡션 대조**: §2-B.

⚠️ **캡처 지점을 「화자가 그 수치를 말하기 시작한 시각」으로 잡으면 거의 항상 이르다.**
도해는 말이 끝난 **뒤에** 완성된다. 촘촘히(1~2초 간격) 뜨고 **가장 늦게 완성된 판**을 고른다.

### 2-B. 🔴 캡션이 그림에 없는 것을 약속한다

자막에서 들은 수치를 캡션에 적고, 그림에는 그 수치가 없는 경우. 2026-09-11 감사에서
**51장 중 23장(45%)** 이 여기 걸렸다.

**처방**: 게시 전 **캡션·그림 정합 감사**를 돌린다(§3-3). 판정은 「대충 맞나」가 아니라
**캡션에서 검증 가능한 항목을 낱낱이 뽑아 하나씩** 본다.

- 비교 대상으로 나열된 **고유명사 전부**가 각각 한 항목(「체리·BYD·지리」 → 3항목)
- 캡션의 **수치 전부**가 각각 한 항목
- **불합격이 하나라도 있으면 불합격** → 재캡처하거나 **캡션을 그림에 맞춰 낮춘다**

🔴 **판정은 O/X 2단이 아니라 3단이다**(2026-09-11 정정 — 2단이라 §2-B-1 의 2건이 샜다).

| 물음                  | 통과 조건                                             |
| --------------------- | ----------------------------------------------------- |
| ① 그림에 **있나**     | 도해에 실제로 찍혀 있다                               |
| ② **자릿수까지 같나** | 화면 「23조5000억」을 캡션이 「23조」로 줄이지 않았다 |
| ③ **표기가 같나**     | 화면 「재쿠」를 캡션이 「제쿠」로 바꾸지 않았다       |

①만 보면 ②③은 **「거짓은 아니다」로 통과한다.** 세 물음을 각각 적어야 한다.

🔴 **자막 띠에만 있는 숫자는 「그림에 있다」가 아니다.** 도해 기준으로 판정한다.

### 2-B-1. 「있나」만 물어서 샌 두 갈래 (2026-09-11 추가)

위 감사가 ①「있나」만 물으면 **거짓이 아닌데 어긋나는 것**은 전부 통과한다.
실제로 2건이 통과한 뒤 게시됐다(리포트 132 · 사후 수정).

🔴 **이 2건은 「못 봐서」 샌 것이 아니다.** 감사 기록(`caption_audit_*.json`)의 `note` 에
_"화면 표기는 '약 23조 5,000억 원'이라 캡션의 '약 23조 원'보다 정확하다"_ 와
_"화면은 '재쿠', 캡션은 '제쿠'로 갈린다"_ 가 **그대로 적혀 있는데도 `pass: true` 였다.**
눈의 한계가 아니라 **판정 기준의 한계**다 — 그래서 처방은 「더 자세히 보라」가 아니라
**§2-B 의 3단 판정을 항목으로 강제하라**다.

| 갈래                  | 실제 사례                                         | 규칙                                                                          |
| --------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------- |
| **수치를 반올림했다** | 화면 「약 23조 5,000억 원」 → 캡션 「약 23조 원」 | 🔴 **캡션의 수치는 화면 표기를 그대로 옮긴다.** 반올림·절사 금지              |
| **표기가 갈렸다**     | 화면 「재쿠 7」 → 본문·캡션 「제쿠 7」            | 화면 표기를 따르되, **본문이 이미 다른 표기로 통일돼 있으면 캡션에 병기**한다 |

🔴 **「기계」와 「읽기」를 혼동하지 말 것**(2026-09-11 사용자 지적으로 정정).
`settle.py`·`verify_yt_report.py` 같은 **토큰 0 스크립트**는 화면 글자를 못 읽어 이 둘을 통과시킨다.
하지만 **Claude 는 PNG 를 직접 읽는다**(`Read` 도구가 이미지를 그대로 띄운다) — §3-3 이 바로 그 단계다.
그러니 이 갈래의 처방은 **사람에게 미루는 것이 아니라 §3-3 의 판정 기준을 3단으로 올리는 것**이다.

### 2-B-2. 자막이 말해도 화면엔 안 뜬 장면이 있다 (2026-09-11 추가)

타임코드를 자막에서 추정하므로, **말로만 설명하고 도해는 안 띄운 구간**을 찍게 된다.
2026-09-11 배치에서 3장이 여기 걸려 드롭했다(`v1_business_segments` · `v1_related_party_96` ·
`v2_suzuki_japan_rank`).

- **드롭이 정답이다** — 없는 화면을 비슷한 것으로 대체하지 않는다. 본문은 글로 서술한다
- 🔴 **드롭은 사후 복구가 가장 비싸다.** 잘못 캡처한 것은 게시된 PNG 를 기준으로 영상에서
  역추적되지만(§2-A), 드롭은 **기준 그림 자체가 없어** 영상을 처음부터 다시 훑어야 한다
- 그러니 **드롭 판정 시점에** 앞뒤 ±60초를 한 번 훑고, 없으면 그 사실을 `selected.json` 밖
  메모로 남긴다 — 다음 세션이 같은 탐색을 반복하지 않도록

### 2-C. 자료 화면이 아예 없는 회차가 있다

2026-09-11 v3(언더스탠딩·딥엑스)는 **72분 내내 슬라이드가 0장**이었다. 217프레임을 20초 간격으로
전수 확인했고 토킹헤드 70% · 스튜디오 20% · 협찬 광고 10% 였다.

**처방**: 억지로 채우지 않는다. `report.md` §7-4 의 마지막 수단대로 **썸네일만** 쓰고 본문은 인용 중심으로 간다.
🔴 **협찬 광고 화면(ETF 배너 등)을 자료로 쓰지 말 것** — 독자가 자료로 오해한다.

**전수 확인 방법**(1차 선별이 0~소수일 때만):

```bash
ffmpeg -i video/<id>.mp4 -vf "fps=1/20,scale=480:-1" -q:v 4 scan/%04d.jpg
ffmpeg -start_number <n> -i scan/%04d.jpg -frames:v 1 -vf "scale=400:-1,tile=6x4" sheets/sheet_NN.jpg
```

🔴 **칸 → 시각 환산은 `(N-1)×20 + 10`초다**(`fps` 필터는 구간 중앙을 뽑는다). 2026-09-11 에
`(N-1)×20` 으로 안내했다가 두 조사자가 10초 이른 화면을 짚었다. **환산식을 쓰기 전에 한 지점을 실측하라.**

### 2-E. 언더스탠딩류는 우측 진행자 패널을 잘라야 한다

`crop.py --prefix v4_,v5_` 로 좌측 72% 보존. ⚠️ **슬라이드가 화면의 76~78% 를 차지하는 회차가 있다** —

finalize 는 그 크롭본이 «지금 선택한 오프셋»이고 원본 프레임보다 새것일 때만 게시용 `png_final/<slug>.png` 로 쓴다.
(예전엔 finalize 뒤에 crop 이 `png/<slug>.png` 를 덮었다 — 선택을 바꾸거나 정각으로 다시 떠도 옛 크롭이 들어갔다.)

### 2-F. 자막으로 추정한 캡처 시각은 화면과 어긋난다 → 정답지부터 (2026-10-27)

자막 타임코드로 그림 자리를 잡으면 화면과 5~15초 어긋난다 — 2026-10-27 Codex·오퍼스 비교에서
그림 자리 약속의 적중률이 **29~40%** 였다. 그래서 순서를 뒤집는다.

1. `python scripts/yt_report/scan.py v1,v2,…` — 영상 전체를 10초 간격 접촉 시트로 훑어
   차트·도해가 **실제로 뜬 시각**을 먼저 적는다(정답지). 칸→시각은 `sheets/<key>/index.tsv` 를 본다.
2. 본문의 `[[FRAME:slug]]` 를 정답지 시각에 매핑하고 `capture.py --exact` 로 **정각 1장**만 뜬다
   (절대 초를 `exact_times.json` 에 기록 → `finalize.py` 가 `frame_times.json` 으로 옮긴다 — §3 의 2번 검사가 이걸 읽는다).
3. 차트 누락 점검(2차 패스)도 같은 표로 끝난다 — 정답지에 있는데 본문에 없는 차트가 누락이다.

🔴 **`settle.py` 의 권장 시각을 되풀이 채택하지 말 것.** 권장을 받아들이고 다시 돌리면 또 뒤로 권하고,
그렇게 끌려가다 **전환 효과(줌·페이드)** 에 닿는다 — 2026-10-27 에 한 장은 흐린 전환 프레임, 한 장은
후미등 클로즈업이 됐다. 권장은 한 번만 보고, 후보 시트를 떠서 **눈으로 확정**한다. 경고가 남아도 된다.

### 2-G. 화면 글자가 자막의 고유명사를 바로잡는다 (2026-10-27)

자동 자막은 고유명사를 소리 나는 대로 받아 적는다. 「(자막 표기)」로 넘기지 말고 **그림 속 글자를 먼저 본다** —
한 회차에서 6건을 화면으로 바로잡았다(에어로노틱스→알레프 에어로노틱스 · 샤인매→샤힌 매 · 위동차→위룽자동차 ·

### 2-H. 🔴 같은 영상이 이미 게시돼 있으면 덮어쓴다 (2026-10-27 · 수리 완료)

`publish.ts` 는 `source_url` 로 찾아 있으면 UPDATE 한다. 새 회차 8편 중 1편이 9월에 게시된 리포트 132 와
같은 영상이었는데 **아무 경고 없이** 본문·제목·썸네일을 덮어썼다. 게시 뒤 손본 최종본은 디스크에 없었다.
→ 이제 기존 글이 하나라도 걸리면 **아무것도 쓰지 않고 멈춘다.** 덮어쓰는 게 맞으면 `YT_ALLOW_UPDATE=v5,…`(또는 `all`).
→ 사용자 지시(2026-10-27) _"앞으로는 이미 올라간 영상인지 확인하고 작업하도록 해"_ — **착수 첫 단계에서 기계가 막는다.**
`fetch_subs.py` 가 자막을 받기 전에 영상 ID 로 `posts` 를 조회해 이미 있으면 멈춘다(같은 `YT_ALLOW_UPDATE` 로 푼다).
덮어쓰기가 맞는 경우(2차 패스·개정판)라도 **옛 판을 먼저 내려받아 둔다** — 게시 뒤 손본 판은 DB 에만 있다.

### 2-I. 게시 확인 검사기가 긴 글의 그림을 「깨짐」으로 셌다 (2026-10-27 · 수리 완료)

`verify.py` 가 4,000px 씩 4번만 내려 39장짜리 글의 아래쪽 16장을 «요청조차 안 된 채» 깨짐으로 셌다(URL 은 전부 200).
바닥까지 내려도 4,000px 도약이 지연 로딩 감지 범위를 지나쳐 남는 그림이 있었다.
→ 측정 전에 `loading=eager` 로 돌려 전부 요청시키고, **받는 중(pending)·못 받음(broken)을 따로** 센다.
「깨짐」이 나오면 먼저 URL 을 `curl -I` 로 찍어 검사기 탓인지 가른다.

### 2-J. 자막이 전부 실패했는데 「성공」으로 끝났다 (2026-11-17 · 수리 완료)

`fetch_subs.py` 가 13편 전부 `NO_KO_SUB` 를 찍고 **`exit 0`** 으로 끝났다. 원인은 자막이 없어서가 아니라
yt-dlp 가 curl_cffi 로 요청하며 넘긴 인증서 경로(`…\1.테스트\…\cacert.pem`)를 curl 이 **한글 때문에 못 연 것**이다
(`curl: (77) error setting certificate verify locations`). 같은 버전으로 10월엔 돌았으니 유튜브 쪽 요청 방식이 바뀐 것으로 본다.
→ `_common.ytdlp_cmd()` 가 인증서를 한글 없는 임시 경로로 복사해 yt-dlp 를 띄운다(`fetch_subs`·`capture` 둘 다).
→ 한 편이라도 자막을 못 받으면 `exit 2`. **`NO_KO_SUB` 가 여러 편이면 자막 부재가 아니라 환경 고장부터 의심**한다.

### 2-K. 두 영상을 한 편으로 합치면 두 번째 영상이 중복 검사에서 빠진다 (2026-11-17 · 수리 완료)

중복 검사(§2-H)는 `posts.source_url` 만 봤다. 합본 글은 `source_url` 에 첫 영상만 들어가므로, 두 번째 영상을
다음 회차에 다시 받으면 **경고 없이 또 게시된다.** → `already_published` 가 본문에 든 영상 ID 도 본다.
🔴 합본 글은 **모든 원본 영상의 주소를 본문에 넣어야** 이 검사가 성립한다 — 첫 문단 아래
`> 원본 영상: [채널 「제목」](주소) · [채널 「제목」](주소)` 한 줄(리포트 172). 상세 화면은 `source_url` 하나만
보여 주므로 독자에게도 이 줄이 두 번째 영상으로 가는 유일한 길이다.
실측(2026-11-17): 고친 뒤 처음 게시한 합본에 이 줄을 빠뜨려 **v11 영상이 안 잡혔다** — 게시 뒤
`already_published([{'key':'v11','id':<영상 ID>}])` 로 「잡힘」을 확인하는 것까지가 합본 게시 절차다.
