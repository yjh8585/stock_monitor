## 1. 한 줄 원칙

**캡션이 약속한 것은 그림에 실제로 찍혀 있어야 한다.**

이 워크플로의 실패는 거의 전부 이 한 줄에서 갈린다. 본문 품질이나 분량이 아니라
**그림이 캡션을 배신하는 것**이 사용자가 반복해서 지적한 결함이다.

## 2. 실제로 터진 결함과 처방

### 2-A. 🔴 애니메이션이 차오르는 중간을 캡처한다 (가장 빈번)

해설 영상의 도해는 **한 번에 그려지지 않는다.** 막대가 하나씩 자라고 표의 칸이 차례로 채워진다.
그 도중을 캡처하면 **표는 분명히 보이는데 비교 대상이 비어 있는** 그림이 실린다.
사람 눈으로 「표가 있다」를 확인하고 통과시키기 때문에 가장 잡기 어렵다.

| 사고                  | 캡션이 약속한 것                        | 실제 그림                                         |
| --------------------- | --------------------------------------- | ------------------------------------------------- |
| 리포트 117 (딥다이브) | 체리·BYD·지리 수출량 **비교**           | 체리 막대만 참, BYD·지리는 축 라벨만              |
| 리포트 122 (대신TV)   | 폭스바겐·도요타 **직원 수 대비 판매량** | 직원 수 행만 참, 판매량 행이 빈칸                 |
| 2026-09-11 v1         | 1분기 실적표                            | 영업이익 행이 빈칸, 영업이익률이 `6.0o` 타이핑 중 |
| 2026-09-11 v1         | 부문별 총이익률 **3개 비교**            | 차량SW 한 칸만 참                                 |
| 2026-09-11 v2         | 체리 러시아 2022·2023·2024              | 2024년 값 라벨만 아직 안 뜸                       |
| 2026-09-11 v2         | 베트남 베스트셀링 1~5위                 | 막대가 다 안 자라 **1위가 제일 짧게** 보임        |
| 2026-09-11 v5         | 합성데이터 라벨 타일                    | 10칸 중 7칸만 참                                  |

**처방 — 세 겹으로 막는다.**

1. **기계**: `python scripts/yt_report/settle.py --check` 를 **게시 전에 반드시** 돌린다.
   선택한 시각 이후 8초를 훑어 **같은 장면인데 잉크(배경 아닌 픽셀)가 더 많은 프레임**이 있으면
   「차오르는 중」으로 잡고 더 늦은 시각을 권한다. 토큰 0.
2. **사람**: 검사기가 잡은 것은 **현재 프레임과 권장 프레임을 나란히 놓고** 눈으로 확정한다.
   🔴 **검사기는 후보를 좁히는 도구이지 최종 판정자가 아니다** — 자막이 길어지거나 하단 고지 띠가
   흐르기만 해도 잉크가 늘어 오탐이 난다(51장 중 1건).
3. **캡션 대조**: §2-B.

⚠️ **캡처 지점을 「화자가 그 수치를 말하기 시작한 시각」으로 잡으면 거의 항상 이르다.**
도해는 말이 끝난 **뒤에** 완성된다. 촘촘히(1~2초 간격) 뜨고 **가장 늦게 완성된 판**을 고른다.

### 2-B. 🔴 캡션이 그림에 없는 것을 약속한다

자막에서 들은 수치를 캡션에 적고, 그림에는 그 수치가 없는 경우. 2026-09-11 감사에서
**51장 중 23장(45%)** 이 여기 걸렸다.

**처방**: 게시 전 **캡션·그림 정합 감사**를 돌린다(§3-3). 판정은 「대충 맞나」가 아니라
**캡션에서 검증 가능한 항목을 낱낱이 뽑아 하나씩 O/X**다.

- 비교 대상으로 나열된 **고유명사 전부**가 각각 한 항목(「체리·BYD·지리」 → 3항목)
- 캡션의 **수치 전부**가 각각 한 항목
- **X 가 하나라도 있으면 불합격** → 재캡처하거나 **캡션을 그림에 맞춰 낮춘다**

🔴 **자막 띠에만 있는 숫자는 「그림에 있다」가 아니다.** 도해 기준으로 판정한다.

### 2-B-1. O/X 를 통과했는데도 그림과 어긋나는 두 갈래 (2026-09-11 추가)

위 O/X 는 「캡션이 약속한 것이 그림에 있나」만 본다. 그래서 **거짓이 아닌데 어긋나는 것**은
전부 통과한다. 실제로 2건이 통과한 뒤 게시됐다(리포트 132 · 사후 수정).

| 갈래                  | 실제 사례                                         | 규칙                                                                          |
| --------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------- |
| **수치를 반올림했다** | 화면 「약 23조 5,000억 원」 → 캡션 「약 23조 원」 | 🔴 **캡션의 수치는 화면 표기를 그대로 옮긴다.** 반올림·절사 금지              |
| **표기가 갈렸다**     | 화면 「재쿠 7」 → 본문·캡션 「제쿠 7」            | 화면 표기를 따르되, **본문이 이미 다른 표기로 통일돼 있으면 캡션에 병기**한다 |

🔴 **기계로는 못 잡는다** — 화면 글자를 읽어야 알 수 있어 OCR 없이는 판정이 불가능하다.
`verify_yt_report.py` 는 이 둘을 통과시키므로 **§3-3 사람 눈 감사에서만 걸린다.**
그 감사에 「수치는 자릿수까지 같은가 · 고유명사 표기가 같은가」를 항목으로 넣는다.

### 2-B-2. 자막이 말해도 화면엔 안 뜬 장면이 있다 (2026-09-11 추가)

타임코드를 자막에서 추정하므로, **말로만 설명하고 도해는 안 띄운 구간**을 찍게 된다.
2026-09-11 배치에서 3장이 여기 걸려 드롭했다(`v1_business_segments` · `v1_related_party_96` ·
`v2_suzuki_japan_rank`).

- **드롭이 정답이다** — 없는 화면을 비슷한 것으로 대체하지 않는다. 본문은 글로 서술한다
- 🔴 **드롭은 사후 복구가 가장 비싸다.** 잘못 캡처한 것은 게시된 PNG 를 기준으로 영상에서
  역추적되지만(§2-A), 드롭은 **기준 그림 자체가 없어** 영상을 처음부터 다시 훑어야 한다
- 그러니 **드롭 판정 시점에** 앞뒤 ±60초를 한 번 훑고, 없으면 그 사실을 `selected.json` 밖
  메모로 남긴다 — 다음 세션이 같은 탐색을 반복하지 않도록

### 2-C. 자료 화면이 아예 없는 회차가 있다

2026-09-11 v3(언더스탠딩·딥엑스)는 **72분 내내 슬라이드가 0장**이었다. 217프레임을 20초 간격으로
전수 확인했고 토킹헤드 70% · 스튜디오 20% · 협찬 광고 10% 였다.

**처방**: 억지로 채우지 않는다. `report.md` §7-4 의 마지막 수단대로 **썸네일만** 쓰고 본문은 인용 중심으로 간다.
🔴 **협찬 광고 화면(ETF 배너 등)을 자료로 쓰지 말 것** — 독자가 자료로 오해한다.

**전수 확인 방법**(1차 선별이 0~소수일 때만):

```bash
ffmpeg -i video/<id>.mp4 -vf "fps=1/20,scale=480:-1" -q:v 4 scan/%04d.jpg
ffmpeg -start_number <n> -i scan/%04d.jpg -frames:v 1 -vf "scale=400:-1,tile=6x4" sheets/sheet_NN.jpg
```

🔴 **칸 → 시각 환산은 `(N-1)×20 + 10`초다**(`fps` 필터는 구간 중앙을 뽑는다). 2026-09-11 에
`(N-1)×20` 으로 안내했다가 두 조사자가 10초 이른 화면을 짚었다. **환산식을 쓰기 전에 한 지점을 실측하라.**

### 2-D. 재몽타주가 조용히 옛 이미지를 남긴다 (수리 완료)

`montage.py` 에 `-y` 가 없어 ffmpeg 이 덮어쓰기를 물어보다 그냥 끝나는데, 스크립트는 `OK` 를 찍었다.
2차 패스 판정자가 **1차 타임코드의 화면**을 다시 보게 됐다. → 2026-09-11 `-y` 추가로 수리.

### 2-E. 언더스탠딩류는 우측 진행자 패널을 잘라야 한다

`crop.py --prefix v4_,v5_` 로 좌측 72% 보존. ⚠️ **슬라이드가 화면의 76~78% 를 차지하는 회차가 있다** —
72% 로 자르면 오른쪽 끝(범례·버튼)이 잘린다. 잘린 게 보이면 `--keep 80` 으로 다시 자른다.

## 3. 게시 전 필수 검사 (순서대로)

```bash
R=scripts/_yt_report/<날짜>
# 1) 본문 기계 검사 — 토큰·H1·백틱·CJK 강조
python scripts/verify_yt_report.py --run $R
# 2) 애니메이션 정착 — 차오르는 중인 프레임 색출
YT_RUN_DIR=$R python scripts/yt_report/settle.py --check
# 3) 캡션·그림 정합 — vision 에이전트에 위임(§2-B 기준으로)
# 4) 조립 → 크롭 → 업로드 → 게시 → 캐시 무효화
YT_RUN_DIR=$R python scripts/yt_report/verify.py --ids <id들>
```

🔴 **2번은 `frame_times.json` 이 있어야 돈다.** 선택한 프레임의 **절대 시각**을 기록해 둘 것 —
오프셋만 남기면 나중에 창 시작(`before`)을 역산해야 하고, 그 값이 좁은 창·넓은 창에 따라 달라 틀리기 쉽다.
